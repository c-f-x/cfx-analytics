# Spike S2: the real SDKs work unchanged

Run on 2026-10-20 under `wrangler dev` 4.151.2, on the owner's Mac (Apple M5 Pro, load average about 2.8, Node 26.8.1). The SDKs were posthog-js 1.438.12 in Playwright's Chromium (build 1248), posthog-node 5.56.2, and posthog-ios 3.92.0 in a macOS command-line target. The code lived on the branch `spike/s2` and is not on master.

## Verdict

S2 passes. All three SDKs delivered everything the spike asked for, with nothing set but the host. The cookieless page also set `cookieless_mode`, which is the site's own privacy choice, not a compatibility setting. 28 of 28 checks passed, on two runs in a row, and nothing was left behind.

## Findings for the real build

1. **posthog-js drops every event from a browser it takes for a bot.** It checks for `HeadlessChrome` in the user agent or the brand list, and for `navigator.webdriver`. Playwright's default headless Chromium trips all three, so the first run got config and flags but no events. The compatibility tests have to present a visitor's browser. That means Playwright's full Chromium in new headless mode (`channel: "chromium"`), `--disable-blink-features=AutomationControlled`, and the user agent without "Headless". The same rule means posthog-js already drops headless bots on the client. Server-side bot marking still matters for the other SDKs and plain fetch.
2. **posthog-js fetches lazy scripts our config switches off.** It loaded `surveys.js` and `dead-clicks-autocapture.js` with `surveys: false` and `captureDeadClicks: false`. Serving every file of the pinned version, as D-15 says, avoids 404s and console noise.
3. **`$pageleave` did not come on a same-tab link navigation** in this headless run. It did come when the page closed. On a full page load, scroll depth rides on `$pageleave`, so behaviour `heatmaps-03` depends on it. This needs a check in a headed Chrome before the scroll-depth query is built. Checked on 2026-10-21 with posthog-js 1.438.12 in Playwright 1.64.1's Chromium: headed, `$pageleave` came on a same-tab link click 3 of 3 times, with `$prev_pageview_max_scroll` 2000; headless, 0 of 3. The miss was headless mode, so `heatmaps-03` can rely on `$pageleave`. Its compatibility test runs headed, or closes the page.
4. **posthog-ios keeps its state on disk outside any run.** A program with no bundle id stores it under `Application Support/com.posthog.unknown/<token>`, and the identified user goes with it. The first run left that folder behind, so the second run's `identify` was a no-op. `HOME` does not move it; `CFFIXED_USER_HOME` does. The compatibility tests point it into the run's scope and fail if the real folder exists.
5. **The browser's `/flags` body is gzip,** because our config offers `gzip-js`. `/flags` has to decode bodies the way intake does.
6. **A Durable Object RPC method that returns `Record<string, unknown>` types as `never`** through `DurableObjectStub`, because `Rpc.Serializable` refuses it. The real slices need serializable return types, or a typed adapter at the call.
7. **The spike's intake read the whole body before checking its size.** The real intake checks `Content-Length` first and stops reading at the limit.
