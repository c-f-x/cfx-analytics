# Audit of the overnight work, 2026-10-22

Five faults were found in the dashboard, the sign-in and the ops commands, and all five are fixed on master with a failing test first. Two smaller gaps in the docs and the deploy plan were corrected. One suspected fault did not hold, and three small items are left, listed at the end.

The audit read the code merged overnight (PRs #16 to #19): the Worker's session, sign-in and dashboard routes, the board's tiles, the web app's screens and query layer, and the operations commands. Each suspected fault was first reproduced, by a probe against the real Worker or by the e2e run, before it counted.

## Corrected in the docs and the plan

- The access table in `docs/architecture.md` named only `/` for the dashboard. It now names `/projects`, `/p/*`, `/app/*` and `/auth/status`, with the unset-secrets rule and the page's headers.
- The deploy's migration undo restores the whole registry to its bookmark. That also drops every product, key and setting changed since, and the plan now says so before it runs.

## Did not hold

- **A failed purge request leaves a deleted product's data forever.** Deleting a product is two requests, and the second only schedules the purge. But the store's own alarm purges any product marked deleted on its next run (`runAlarm`, privacy-20). So a failed purge request delays the purge to the next daily alarm and loses nothing.

## Left

- The heatmap asks once with band 0 to learn the page's bands, and that request also looks up a snapshot nobody uses. It is one extra store read per page view of Pages, so it is cheap, and the fix is an API change.
- An internal-traffic rule's value is entered as text, or true and false. A numeric property such as `42` cannot be matched, because rules match exactly as written. Doing this needs a type choice in the rule form.
- The e2e run lets "Failed to load resource" console lines pass, because the unknown-product check expects a 404. That is how the missing favicon went unseen until staging. A narrower filter would name the expected path.

## Checks

`pnpm check` passed (857 tests: the Worker's 832, the shared package's 18 and the dashboard's 7; the size tests; both builds). `pnpm e2e` passed 30 of 30, `pnpm compat` 19 of 19 and the guard proof every case. After the merge, staging was redeployed with `pnpm ops deploy staging --go` and checked with `pnpm smoke staging`.
